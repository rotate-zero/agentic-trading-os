# Confirmed Decisions

**Extracted from:** `../architecture/system-design.md` §9 (original numbering preserved for continuity with any existing references).
**Companion documents:** [`../architecture/system-design.md`](../architecture/system-design.md) (how it's built), [`../architecture/trading-intelligence-architecture.md`](../architecture/trading-intelligence-architecture.md) (how it thinks), [`future-ideas.md`](./future-ideas.md) (deferred, not rejected), [`../roadmap/phase-roadmap.md`](../roadmap/phase-roadmap.md) (when things ship).

This is the running log of settled architecture decisions — the "why did we choose X" record, kept in one place instead of scattered as inline asides across growing documents. **New confirmed decisions get appended here, numbered sequentially, as part of the same change that makes them** — not batched up and written after the fact.

1. **Broker order of implementation** — Alpaca first, then IBKR. (`../roadmap/phase-roadmap.md`, Phase 3)
2. **Candle storage** — plain PostgreSQL with native monthly partitioning for v1. TimescaleDB is deferred, revisited only once multi-timeframe backtesting at scale is a real, not hypothetical, requirement — since it's an additive extension, deferring costs nothing later. (`../architecture/system-design.md` §6.1, §4.13)
3. **Scanner cadence** — variable, config-driven schedule keyed to session windows (tight at open/close, sparse midday) rather than a fixed interval. (`../architecture/system-design.md` §4.7)
4. **Redis** — skipped for v1. Revisit if/when agents move to separate processes. (`../architecture/system-design.md` §6)
5. **Context Engine is a composed aggregator**, not a monolithic module — one provider per context question, so growth (news, OPEX, breadth, sentiment) means adding a provider, not editing a growing conditional block. (`../architecture/trading-intelligence-architecture.md` §5)
6. **Governor's decision schema is widened now, implemented narrow.** `GovernorDecision` supports `approved | approved_reduced | delayed | watch_only | rejected`; v1 rule logic only ever produces `approved`/`rejected`. A schema change now avoids a breaking change to every downstream consumer later. (`../architecture/trading-intelligence-architecture.md` §12)
7. **World View is a read-only composite facade**, not a shared mutable world model. Assembles Market State + Portfolio State + Context + Performance Intelligence for consumers that want the whole picture at once (debug tooling, a future LLM reasoning layer). No write path, no state of its own — single-writer-per-domain stays intact. (`../architecture/trading-intelligence-architecture.md` §15)
8. **Event data contracts are formalized before Phase 1 code**, not discovered along the way. (`../architecture/system-design.md` §10)
9. **Event Bus dispatch is two-lane, not multi-tier priority.** Execution-critical events (`OrderFilled`, `PlanRejected`, `GovernorDecision`, `OrderApproved`) get an isolated dispatch lane so they're never delayed behind market-data volume; everything else shares one normal lane. A general N-tier priority framework was considered and rejected as complexity without demonstrated need at this scale (single process, ~100-symbol universe, Scanner-narrowed to a handful). (`../architecture/system-design.md` §4.4)
10. **Stateful engines that need periodic-but-not-constant recompute (Market State Engine, Position Monitor) use a shared `DebounceScheduler` utility** — event-triggered, with a minimum interval (don't recompute more than once per N seconds) and a maximum interval (recompute at least once every M seconds even if nothing changed). Same pattern already used for Scanner cadence and Strategy triggers, implemented once and reused rather than each module inventing its own timer logic. Feature Engine, Governor, and Execution Engine do **not** use this — they react to every event with no debounce, since staleness there is either wrong indicator values or a safety issue. (`../architecture/system-design.md` §8, `core/debounce_scheduler.py`)
11. **`docs/` is the authoritative location for all architecture and design documentation**, organized into `architecture/`, `decisions/`, `diagrams/`, `roadmap/`, and `api/` subfolders. Implementation code stays separate from documentation. Any future architecture change updates the relevant document(s) here as part of the same change that makes the change — not a follow-up task. (`../README.md`)
12. **Partition-boundary literals in migrations must carry an explicit UTC offset (`+00`), never a bare date.** Found via a real local-Postgres run: a bare `'2026-07-01'` literal in `CREATE TABLE ... PARTITION OF` gets interpreted using the DB session's local `TimeZone` setting at migration-run time, not UTC — so the same migration produces a different physical partition boundary depending on who/where runs it (observed: a session with `TimeZone=Asia/Dhaka` produced a boundary six hours off from intended UTC midnight). Fixed in `0001_initial_symbols_and_candles.py` by writing boundaries as `'2026-07-01 00:00:00+00'`. Applies to every future partition-seeding migration, not just this one.

**Deferred, not rejected** — Knowledge Engine, Attention Engine, uncertainty propagation across the pipeline, the full write-everywhere World Model, Replay Engine, and Simulation Mode all live in [`future-ideas.md`](./future-ideas.md) with the reasoning for why each is parked, and what would trigger revisiting it.

No open items remain blocking Phase 1–3. Next natural checkpoint is Phase 4/5, where the Timescale question gets revisited against real backtesting requirements.
