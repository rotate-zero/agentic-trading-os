# Phased Roadmap

**Extracted from:** `../architecture/system-design.md` §7.
**Companion documents:** [`../architecture/system-design.md`](../architecture/system-design.md), [`../architecture/trading-intelligence-architecture.md`](../architecture/trading-intelligence-architecture.md), [`../decisions/confirmed-decisions.md`](../decisions/confirmed-decisions.md), [`../decisions/future-ideas.md`](../decisions/future-ideas.md).

Each phase should be a mergeable, demoable slice — no phase depends on unfinished code from a later phase.

| Phase | Deliverable | Exit criteria |
|---|---|---|
| 1 | React + Lightweight Charts, static candle JSON, custom drawing support | Chart renders candles + one of each overlay type from a static file |
| 2 | FastAPI backend, Event Bus + Market Clock scaffolding, WebSocket channel plumbing, PostgreSQL + Alembic wired | Chart receives live overlay pushes over WebSocket instead of static file; a dummy event round-trips through the Event Bus |
| 3 | One broker adapter — IBKR (Alpaca not available for a Bangladesh-resident account; see `../decisions/confirmed-decisions.md` #1) | Live ticks for 1 symbol flow adapter → engine → chart |
| 4 | Full Market Data Engine + Feature Engine: multi-symbol subscribe, normalize, cache, persist, compute features once | 100-symbol universe streaming with a `FeatureSet` published per symbol, no dropped ticks |
| 5 | Scanner + Strategy Engine + Opportunity/Decision/Planning Engines + Governor + Portfolio State Engine | Opportunities appear on chart with confidence, entry/stop/target; Governor can reject a plan against Portfolio State |
| 6 | Execution Engine (dry-run first, then live) + Position Monitor | Approved plan produces a paper order end-to-end; Position Monitor flags an open position as "weakening" |

## Status (living — update as phases complete)

- **Phase 1 — done.** Multi-tab Main Windows, 8×8 grid picker, ticker search, nested sub-window menu, candle-count stepper, per-sub-window background color, localStorage save/load. See repo `README.md` for verification notes.
- **Phase 2 — backend scaffold delivered, frontend swap paused.** FastAPI skeleton, Alembic + PostgreSQL (plain, no TimescaleDB — decision #2), Event Bus with two dispatch lanes (decision #9, verified: a test proves a slow normal-lane subscriber cannot delay a critical-lane event) + Market Clock, `DebounceScheduler` utility (decision #10, unit-tested but not yet wired to a real consumer — Market State Engine doesn't exist until Phase 5), WebSocket gateway. Round-trip exit criterion (dummy event through the Event Bus, out over WebSocket) verified live end-to-end, DB migration verified against a real local Postgres. Frontend mock-data swap (candles.ts → live WS feed) was started, then paused to prioritize the broker adapter — plan unchanged, now has a real data source to point at.
- **Phase 3 — functionally complete end to end (adapter → chart), two of three connections unverified live.** Broker order revised: IBKR only for execution (decision #1) — Alpaca isn't open to Bangladesh-resident accounts. Data-vendor evaluation (`decisions/future-ideas.md` #17) added Polygon.io (historical backfill, 15-min delayed free tier — decision #30) and Finnhub (real-time streaming, no historical on free tier — decision #32) once IBKR account access took longer than planned. `MarketDataProvider`/`BrokerAdapter` split (decision #28) lets both coexist cleanly; a two-role `broker_registry` (streaming/historical — decision #33) coordinates them, auto-connecting on startup if configured. `TickIngestBridge` (renamed from `IBKRIngestBridge`, decision #31) buckets ticks into 1-minute candles for any provider — still a Phase-3-minimal stand-in for Phase 4's real Market Data Engine, not the real thing. Frontend mock-swap resumed and completed for `candles.ts` (decision #35) — a real chart now renders real (or provider-appropriate delayed) data via `useLiveCandles`, `useLatestPrices`, and a shared WebSocket client, through a new provider-agnostic `POST /market/subscribe` route. `chartObjects.ts`/`opportunities.ts` remain correctly mocked, gated on Phase 4/5. **Verified:** `ib_async` API signatures, tick-bucketing, qualification/disconnect handling, `PolygonAdapter`/`FinnhubAdapter` logic (the latter against a real local WebSocket server mimicking Finnhub's protocol), the two-role registry's coordination logic, and a full TypeScript build + CORS/error-shape check against a real running backend. **Not verified: IBKR against a real Gateway/account** (passport renewal pending), and **neither Polygon nor Finnhub against real API keys yet** (in progress on your end — no path to `wss://ws.finnhub.io` or live Polygon calls from the environment these were built in). 2FA strategy for IBKR documented (decision #14): IB Key + Gateway auto-restart, not SMS, not a claim of full headless operation.
- **Phase 4 — started: backend Feature Engine's first indicator, plus its first real downstream consumer.** SMA now computed server-side (`app/feature_engine/{indicators.py,engine.py}`, decision #45) from persisted `1m` candles, published as `FeaturesUpdated` on the Event Bus — the first real output on "the one canonical Feature Engine path" (system-design.md §1), replacing the frontend-only SMA that decisions #40/#41 always scoped as view-only. Scoped narrowly and deliberately: `1m` only (no `5m`/`15m`/`1h` yet — see decisions #45/#46), SMA only (EMA/VWAP/ATR/PDH-PDL/relative volume/gap %/opening range/trend slope all still the target shape from §4.5, not yet built), and no `feature_snapshots` persistence yet (§4.5's own rule: persisted at decision time, and Strategy Engine doesn't exist yet to have a decision time). On top of that, the Level Interaction Engine (`app/trading_intelligence/level_interaction_engine.py`, decision #46) is now built and wired in — touch/holding/rejected/conquered tracking, generic across any level key Feature Engine publishes, not SMA-specific. Worth naming the phase-boundary blur explicitly: system-design.md §4.8 places this module conceptually alongside Market State/Context/Strategy Engine — Phase 5 territory by the table above — but it only depends on `FeaturesUpdated` already existing, so it got built now rather than waiting on Scanner/Strategy Engine/Governor, which it doesn't need. **Verified:** full backend suite (108 tests, up from 90) against a real local Postgres — 8 for Feature Engine (including a real cold-start/restart-survival test) and 10 for Level Interaction Engine (including gap-through, cold-start-unknown-origin, day-rollover reset, and its own restart-survival test); two real Alembic migrations (`0001`, `0002`) applied cleanly; a real `uvicorn` process boots with all three engines (`CandleRecorder`, `FeatureEngine`, `LevelInteractionEngine`) wired in and `/health` responding normally. **Not verified:** no real market-data tick has flowed through either engine yet — only synthetic events published directly, not a live `FinnhubAdapter` session (the pre-market/after-hours checks so far confirm `/health` and startup logs, not real feature/level output). Full Phase 4 exit criterion (100-symbol universe, no dropped ticks, full feature set) is still ahead — this is two slices, not the whole phase. Not yet started: the market scanner (design discussed, not coded — see `future-ideas.md`), extending SMA/Level Interaction to `5m`/`15m`/`1h`, and a live "still holding, updating every candle" event stream (deliberately deferred in decision #46). Two judgment calls in decision #46 (gap-through anchor price, cold-start-unknown-origin classification) are flagged for confirmation, not yet signed off. Decision #47 adds the backend read side for the Feature Engine panel — `get_snapshot()` on both engines, `GET /intelligence/state`, and both engines now reach the WebSocket Gateway for the first time — plus three real shutdown bugs found and fixed along the way (fire-and-forget `stop()`, backwards shutdown order, a missing `try`/`finally` in `lifespan()`). Full suite: 113 passed, verified stable across 5 consecutive runs. **Decision #48 builds the frontend panel itself** — the first real consumer of `GET /intelligence/state`, generic across whatever Feature Units the backend actually publishes (today: SMA only). `tsc -b`/`vite build` both clean; a real simultaneous backend+frontend boot confirmed the network path and CORS work end to end. Not yet click-through verified in an actual browser.
- **Phase 5–6 — not started.**
