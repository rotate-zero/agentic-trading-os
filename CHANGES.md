# CHANGES — decision #141 (D19 Daily Levels run isolation)

Backtest Daily Levels reconciliation is now isolated by `backtest_run_id`, so separate runs of the same ticker cannot update or archive one another's persisted level identities.

## What changed

- Added nullable `daily_levels_state.backtest_run_id` with a real FK to `backtests.run_id` and `ON DELETE CASCADE`.
- Added a database CHECK requiring live rows to have no run ID and backtest rows to have one.
- Threaded the UUID generated by `BacktestRunner` through `EngineBackedReplayStateProducer` into `FeatureEngine`.
- Scoped Daily Levels reconciliation, inserts, and the restart-survival read to the selected run ID.
- Replaced the old `(symbol_id, status)` index with `(symbol_id, is_backtest, backtest_run_id, status)`; the existing level-identity unique constraint is unchanged.
- Migration `0010` removes only legacy backtest Daily Levels rows that cannot be assigned honestly to a run. Live rows and every other symbol-dependent table remain unchanged.

The cascade deliberately differs from `strategy_outcomes.backtest_run_id`'s default `NO ACTION`: outcomes are durable analytical records, while Daily Levels rows are derived run checkpoints. Current application code has no backtest-deletion path, and no table references `daily_levels_state.id`.

Documentation adds D19 to `strategy-engine-design.md` without changing resolved D18 and records decision #141 in the decision log and index.
