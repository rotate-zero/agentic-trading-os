# CHANGES — pending decision (temp id: `data-feed-status-indicator`) — Finnhub/Polygon data feed status surfaced in the header

**Decision number intentionally not assigned** — see this delivery's entry in `confirmed-decisions.md` (appended after #142) for why, and for the number to assign at merge time (143, per a three-source check at packaging time, unless a parallel session lands first).

Two real, working backend routes — `GET /finnhub/status`, `GET /market-data/status` — had zero frontend representation; only `curl` could ask whether either provider was actually connected. This closes that gap with a small, read-only, always-visible header indicator, plus one deliberate exception: a Finnhub-only manual reconnect action.

## What changed

- **New `frontend/src/components/header/DataFeedStatus.tsx`** — two compact badges (Finnhub, Polygon), each showing connected/disconnected via a small colored dot (green = connected, muted gray = disconnected — deliberately not this app's `bear`/red token, since a routine disconnect for these two optional providers isn't an error state). Polygon's badge also shows its current `role` (`"historical+streaming"` vs. plain `"historical"`) when connected, since Polygon can be promoted to the streaming role as a fallback (decision #33) and collapsing that into a boolean would hide real information. Mounted in `App.tsx`'s `<header>` in both shells (`FullWorkspaceShell` and `PoppedOutWindowShell`) — not a new `<main>` panel, which is the shape a parallel IBKR connection-panel session needs, not this lower-stakes read-only one.
- **New `frontend/src/hooks/useDataFeedStatus.ts`** — polls `GET /finnhub/status` + `GET /market-data/status` every 120 seconds via `Promise.allSettled` (each provider's fetch failing independently never blanks the other's good reading; a failed fetch leaves the previous reading in place rather than fabricating "disconnected"). Pure-poll by necessity, not choice — grepped `backend/app/api/websocket/channels.py`'s `EVENT_TO_CHANNEL` directly and confirmed no `EventType` exists for a provider connecting/disconnecting, so unlike `useContextSnapshot.ts` there's no WebSocket push to be primary over. The 120s interval is deliberately looser than that hook's own 60s poll — full reasoning inline in the hook's `POLL_INTERVAL_MS` comment.
- **`frontend/src/services/api-client.ts`** gained three additive exports: `fetchFinnhubStatus()`, `fetchMarketDataStatus()`, and `connectFinnhub()`, plus their wire-shape types (`FinnhubStatusWireShape`, `MarketDataStatusWireShape`, `FinnhubConnectResultWireShape`). Nothing existing in this file was changed.
- **`frontend/src/App.tsx`** gained one new import and one `<DataFeedStatus />` mount inside each header's existing right-hand button group, ahead of `LayoutsMenu`/`GridPicker`. No existing lines removed or reordered beyond wrapping that group in one new flex container for spacing.
- **A Finnhub-only manual "Reconnect" button**, wrapping `POST /finnhub/connect`, appears on the Finnhub badge only when it's disconnected. This is the one deliberate scope exception in this delivery: `backend/app/broker_adapters/finnhub_provider.py`'s own `_listen()` sets its connected flag `False` on an unexpected WebSocket close with **no auto-reconnect** — that file's own comment defers the fix to a not-yet-built Phase 4 `ConnectionManager` — so today, calling `POST /finnhub/connect` again is genuinely the only way to restore a dropped session, and there was no UI path to do that at all before this change, only `curl`. Found while reading the required background material for this task, presented to Saqib as a fork before writing any code, confirmed: add the button. Polygon was checked for the same class of gap and found to have none — it's REST-polling based with no persistent socket to drop (`PolygonAdapter`'s own docstring) — so it deliberately gets no matching button.
- **`docs/architecture/system-design.md` §4.2** gained an as-built note with two ASCII diagrams (cross-component data flow; the new hook/component's internal poll-and-reconnect flow), matching this doc's existing plain-fenced-code-block diagram convention (no Mermaid used anywhere in this repo's docs, confirmed by grep before choosing a format). No architecture doc was found actually claiming this status was unsurfaced in the UI (checked directly via `grep -rn "finnhub|polygon" docs/architecture/`), so this is a new note, not a stale-claim correction.

## What did not change

- Nothing under `backend/` — this delivery is frontend-only, since both routes it surfaces already existed and worked.
- `backend/app/api/routes/broker.py` / `backend/app/broker_adapters/` — read-only reference during this task's research (a parallel session may be building the IBKR panel there), never edited.
- `App.tsx`'s `<main>` panel list, and everything under `frontend/src/components/backtest/` / `backtest-results/` and their hooks — out of scope, untouched.
- No new backend route, no new WebSocket channel, no schema/migration change.
